## Findings

### JE-1 MAJOR, CI and deploy, high confidence

`CLAUDE.md` lines 8 to 9 and `README.md` lines 3 to 4: Next.js on Vercel, auto-deploy on every push to `main`. The tip has no `.github` directory (GitHub contents API 404 at this sha). The Actions workflow list is empty (`total_count` 0). `package.json` scripts are `dev`, `build`, and `start`.

Branch protection and rulesets both return HTTP 403 because this private repo is on a plan that does not offer them. A required check cannot be attached to `main` from here.

`renovate.json` extends `local>DrDustinEdwards/devkit` and sets top-level `automerge` to false. The preset's package rules still set `automerge` true for non-major groups, and a package rule wins over that top-level false. The preset also leaves `ignoreTests` false. Devkit's own note on that preset says a repo with no CI never automerges, because Renovate refuses to automerge without a passing check. This repo has no check, so those grants do not fire today. The day a workflow exists and is green, the preset's non-major grants start merging, and each merge is a production deploy.

What goes wrong: a push to `main` that Vercel can build becomes the live site with no review and no separate test or audit job. `next build` does typecheck, so a type error fails the build. This audit did not open the Vercel project, so it cannot see whether a failed build is held. A change that builds and is still wrong (copy, headers, a dependency a person merges) has no earlier gate.

Smallest fix: add a workflow that runs `tsc --noEmit`, `npm run build`, and `npm audit`, and set the Vercel production deploy to wait for that check. Keep `automerge` false in a package rule that wins over the preset before that workflow exists, or the first green CI run starts merging non-majors into production. A GitHub ruleset is not available on this plan.

### JE-2 MINOR, security, high confidence

`next.config.mjs` lines 1 to 13 and line 40. The CSP is `Content-Security-Policy-Report-Only`. `script-src` allows `'unsafe-inline'` and `https://va.vercel-scripts.com`. `style-src` allows `'unsafe-inline'`. The header has no `report-uri` and no `report-to`. The comment says to enforce once the report stream is clean. There is no stream.

The live homepage, `/llms.txt`, `/robots.txt`, `/sitemap.xml`, the 404, and `/opengraph-image` all send that same report-only policy, plus HSTS `max-age=63072000; includeSubDomains; preload`, `X-Frame-Options: SAMEORIGIN`, `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and `Permissions-Policy: camera=(), microphone=(), geolocation=()`. Those match the file.

What goes wrong: a script injected into a page would run. Nothing in this tree puts a request, a query string, or a stored body into HTML. The theme script and the JSON-LD are constants. The risk is the policy that would have contained a future bug, and a comment that waits on reports nobody is collecting.

Smallest fix: hash or nonce the theme script and the two JSON-LD scripts, drop `'unsafe-inline'` from `script-src`, and send `Content-Security-Policy`. Inline style props in `Contact.tsx` still need a style nonce or `'unsafe-inline'` on `style-src`. Add a report endpoint only if the policy stays report-only for a while.
